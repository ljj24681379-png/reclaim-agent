01
先立判据：什么才算「创造新价值」
在讨论方向之前，必须先回答一个会被面试官当场追问的问题：凭什么说这不是提效？ 我的判据是四条，任何一条不成立，这个产品就是套壳。
维度提效型 Agent创造新价值型 Agent
价值函数 价值 =（原成本 − 新成本）× 存量需求量。存量被锁死，随替代率提升边际递减。 价值 = 新增行为量 × 单次价值。此前这个数是 0，不是被压缩的问题。
反事实检验 没有它，事情照样发生，只是更慢、更贵、更累。 没有它，这件事根本不发生——不是做得慢，是不做。
旧世界 存在一个被优化的既有流程／岗位／工具。 不存在对应流程，也不存在承担该角色的职业。
结算方式 按使用量、席位、订阅收费；价值难归因到结果。 按结果结算——每一笔交付都有确定金额。
模型依赖 换个更强的基座模型，效果立刻被吃掉（套壳风险）。 壁垒在权益图谱、执行闭环、授权与信任，模型是零件不是产品。

四条判据如何逐条成立

判据一行为从无到有
睡眠保单专项中，机构已完成有效提醒 732.07 万件，实际领取仅 180.49 万件——领取率 24.65%。 需求不是「不知道」，而是知道了也不动。行为缺失可被直接量化。
判据二供给角色不存在
现实里没有任何职业或机构，在替个人系统性地管理全部权益。 律师受客单价约束不做、机构只管自己家的、平台与用户利益对立。没有「个人权益管理人」这个岗位可被提效。
判据三非 LLM 不可
权益依据散落在 N 个平台的自然语言条款中且频繁变更——规则引擎写不出来； 兑现要跨数周多轮博弈——人力注意力撑不住；用户不知道自己有什么——响应式产品无法启动。
判据四价值可结算
每笔兑现都有确定金额、到账凭证、时间。因此可以「成功才收费」， 用户零风险起步，且与结果强对齐——这正是 Proactive Agent 从「执行工具」变成「任务结算单位」的关键。
为什么「主动性」是这个产品的必需品，而不是锦上添花

绝大多数 Agent 是 Reactive 的——等你提问。但在这个场景里，用户不知道自己有什么权益，因此永远不会发起第一次提问。产品无法被用户主动触发，只能由 Agent 主动发现。

这不是一个产品偏好问题，而是需求本身决定的架构约束。学界把 Agent 的主动性分为三级：Reactive（等指令）／Scheduled（定时触发）／Situation-Aware（跨源感知变化、判断何时打断）。归仓必须做到第三级。

而这一级目前模型普遍做不到：小米 ProactiveMobile 基准上，GPT-5 成功率仅 7.39%，表现最好的微调模型 Qwen2.5-VL-7B 也只有 19.15%。这个 7%→19% 的鸿沟，就是产品机会与技术壁垒同时存在的地方。

推翻了「提醒即解决」。机构已经用尽触达手段，仍有约 3/4 的人拿不回自己的钱。这直接否定了「做个权益提醒机器人／加个消息推送」的常规方案——那是把已经失败过一次的事再做一遍。

真正的断点在「从知道到拿到」之间的行动链，它有三处断裂：

断点 1不信
在电诈高频环境下，一条「您有 4.8 万元满期金待领取」的短信，正常人第一反应是诈骗。 中消协调查中，放弃维权者 23.1% 归因「对监管没信心」。机构越主动，用户越怀疑。
断点 2不会
举证难（22.3%）、程序复杂（22.3%）、不熟悉法规（22.7%）、渠道少（24.3%）。 中消协 2025 年调查中「默默忍受」群体的前四位原因，全部指向行动能力缺失。
断点 3不动
公开总量显示大量投诉单体价值可能较低，而维权要跨协商→平台→监管→诉讼多级阶梯、耗时数周。 收益低于心理成本，于是拖延到放弃。商家恰恰拿捏「不值得较真」而推诿。

03
供给真空：四种现存方案，没有一种成立
需求侧的证据只说明「有人需要」。要证明这是新市场而非存量竞争，必须说明现有供给为什么都接不住。
现有供给它实际在做什么为什么接不住这个需求
律师 / 法务 承接有明确标的额的诉讼与非诉业务。 很多争议单体金额低、处理链路长，难以覆盖正式法律服务的人工成本。不是没有需求，是传统价格带难成立。
消费者自己 协商 → 平台申诉 → 12315 → 诉讼。 举证几乎全部压在个人身上；要拍摄开箱视频、保留检测报告、读懂条款。流程长、规则多、单次收益低，理性选择就是放弃。
机构（保险/银行/平台） 合规驱动的单向提醒：短信、电话、信函、上门走访。 只覆盖自己家的权益，出于监管压力而非用户利益；且触达方式是用户最不信任的形态——数据已证明领取率仅 24.65%。
「职业代退」黑产 话术模板 + 伪造证据（如要求客户去医院开虚假病历）+ 恶意投诉施压，抽成约 30%。 《工人日报》《泉州晚报》等报道其已形成团伙化分工，衍生个人信息泄露、二次诈骗、敲诈勒索。这是真实需求在非法侧的表达。
关键推论

一个规模巨大、需求真实的市场，合法的低价供给不存在，非法的供给在蓬勃发展。 这说明瓶颈从来不是需求，而是「合法 + 低价 + 可规模化」这三者在旧技术条件下无法同时满足。

Agent 的出现第一次让三者可以同时成立：边际执行成本趋近于零（可规模化、低价），过程全程留痕且不依赖虚假陈述（合法）。这就是新价值。

竞品证伪：为什么不能做「DoNotPay 中国版」

DoNotPay 是这个方向最知名的先驱，也是最好的反面教材。它的失败方式精确地指出了产品该往哪走。

失败 1卖模板，不卖结果
美国 FTC 在最终裁定中认定：该公司从未测试过其输出是否达到真实律师水平，且未雇佣任何律师。 核心能力停留在「填好你的名字的格式化信函」——而这恰恰是用户自己也能做的事。
失败 2宣称替代专业角色
FTC 2024 年 9 月起诉、2025 年 1 月最终裁定，要求支付 19.3 万美元 救济金、 通知 2021–2023 年订阅者，并禁止在无证据情况下宣称「等同于真人律师」。2026 年其官网已改为「AI Consumer Champion」并声明非律所。
失败 3信任被自身产品反噬
Trustpilot 1.8 / 5（379 条评价，73% 为一星），价格不透明， 且「帮用户取消订阅」的产品自身被大量投诉难以取消订阅——信任是这类产品的生命线。
由此确立的三条设计铁律

1. 交付结果，不交付文书。用户买的不是一封信，是「钱到账」。产品架构必须是执行闭环 + 结果结算，而不是内容生成。

2. 明示依据，绝不越界。每一条主张必须落到具体条款原文与来源；涉及虚假陈述、伪造证据、代替用户做法律行为的动作，一律在设计层拦截——这既是合规底线，也是与黑产的分界线。

3. 产品自身必须无可指摘。 pricing 透明、授权可撤销、数据可导出、全过程可审计。任何「 irony 」都会直接摧毁信任基础。

04
产品方案：五层架构与一张权益图谱
产品不是「AI 帮你写投诉信」。它是一个持续运行的系统：发现 → 判定 → 兑现 → 留痕， 外加一条贯穿始终的合规闸门。

4.1 数据底座：把「权益」变成可计算对象

一切能力的前提，是把散落在各处的自然语言条款，结构化为统一 schema。这是产品的核心资产，也是模型无法替代的壁垒。

字段含义实例（航班延误补偿）
domain权益所属域出行 · 航空运输
trigger可机读的触发条件实际到达延误 ≥ 4h 且 < 8h，且原因归类为承运人原因
basis依据条款（法条 + 承运/服务条款原文）《航班正常管理规定》第 29 条；承运人《运输总条件》补偿标准
evidence举证要求清单登机牌、航班实际起降时间记录、延误原因证明
path兑现阶梯（含每级时限）承运人协商 → 民航服务质量监督平台 → 诉讼
window时效窗口自航班日起 2 年（民法典普通诉讼时效 3 年，按承运条款收紧）
amount候选涉及金额¥200（依国航 2026 年 4 月版条款示例）
p_success历史成功率（分场景校准）0.82
cost兑现综合成本（Agent 算力 + 人力兜底）¥6.4
由此得到的产品决策：期望价值（EV）闸门

EV = 期望金额 × 成功率 − 兑现成本。EV 低于阈值的权益不主动推送，仅折叠进「低价值」区，用户可自行展开。

举例：一笔外卖超时赔付 ¥8，成功率 0.9，成本 ¥12 → EV = −¥4.8，不打扰。

这是反直觉但必要的取舍：主动式产品的生死线是「不骚扰」。每一次无价值的推送，都在消耗用户对「主动」这件事的容忍度——而这正是行业指标 Proactive 接收率 所衡量的东西。

4.2 系统架构

4.3 三个决定成败的产品设计

设计一权益卡必须自带「判决书」
每张权益卡必须包含：依据条款原文（可点开核验来源）、期望金额与成功率、 EV 计算过程、举证清单、路径与时限。 目标是让「不信」这个第一断点在用户点开的第一屏内被解决——不是靠话术，靠可复核。
设计二合规闸门是护城河不是成本
凡涉及虚假陈述、伪造证据、代替用户做法律行为、未经授权外发个人信息的动作，在架构层直接拦截并留痕。 这既是监管底线，也是与代退黑产的根本区别，更是B 端机构愿意合作的前提——保险公司不会和一个可能教唆骗保的产品合作。
设计三分级授权，而非全权委托
L0 自动（监控、查询、生成草稿）／L1 一键确认（发送申请、补充材料）／ L2 显式授权（金额承诺、个人信息外发、法律文书）／L3 永久禁止（伪造、代签、虚假投诉）。 把「敢不敢授权」拆成可渐进的小决策，降低首次授权门槛。

06
指标体系：北极星与它的四个制约项
这类产品最容易死在「发现得越多越骚扰用户」。因此北极星不能只看兑现金额，必须绑定质量与信任指标。
北极星指标

月度已兑现权益总额（Settled Entitlement Value, SEV）＝ Σ 实际到账金额。

选它的理由：它同时代表用户价值、B 端价值与可结算收入，且无法被刷量指标伪造——到账就是到账。

① 误报率 False Claim Rate　一票否决
推送后被判定为不成立、或用户明确标记「这是骚扰」的比例。这个指标直接决定信任资产，一旦失控，全部其他指标归零。
目标 < 5%
② 主动接收率 Proactive Acceptance
推送的权益中用户接受并授权兑现的比例。这是 Proactive 类产品最核心的产品指标——衡量「该不该推、推得对不对」，而非技术能力。
目标 > 55%
③ 兑现成功率 Claim Success Rate
已授权兑现的权益中最终到账的比例，按 domain 分场景统计，反哺权益图谱的 p_success 参数校准。
分层：高置信 > 85%
④ 单位兑现成本 Cost per Settlement
单笔兑现消耗的 Agent 算力 + 人力兜底摊销。它决定了 EV 闸门的阈值，也决定低价市场能否被合法覆盖。
目标 < ¥15 / 笔
⑤ 首次授权转化率
注册用户中完成首个数据源授权的比例。这是整个产品的入口瓶颈——没有授权就没有发现，分级授权设计主要服务于它。
目标 > 40%
⑥ 平均兑现时效 T+（天）
从授权到到账的天数，按兑现阶梯分级统计。长周期场景（如保单）需单独设档，避免污染短周期指标。
短周期 < 7 天

评测体系：高风险场景必须有的四道闸

  • 真实 Query 评测集：从真实权益场景抽样构建评测集，不只用合成数据——合成数据无法覆盖条款冲突、平台话术变化、举证缺失等真实复杂度。
  • 依据溯源率：每条权益主张必须能落到可核验的条款原文与来源；无法溯源的一律不推送。这是「不信」断点的技术解法。
  • BadCase 归因回流：失败案例按「依据错误／举证不足／话术失效／对方无理拒绝／越权违规」五类归因，分别回流到图谱、材料、协商、升级、合规闸门五个模块。
  • 模型分场景选型：判定层（强规则理解）与协商层（强对抗与语境）用不同模型与温度参数，不追求一个模型打天下；以依据溯源率和协商成功率为选型标准，而非通用榜单。

商业化：为什么 B 端才是规模化的那一边
价值可结算既是产品的优势，也是商业模式的设计起点。但这个市场的付费方不止一个。
付费方付费动机计价方式为什么成立
C 端用户 零风险拿回本属于自己的钱；省去举证与沟通成本。 按结果计费 10–20%；会员制解锁主动监控与无限次。 价值金额确定、到账可验证，成功才收费使首次尝试门槛趋近于零。参考：Rocket Money 账单谈判按首年节省额抽成 35–60%；代退黑产抽成约 30%。
保险公司 睡眠保单清理是监管强制的合规动作，人工排查 + 上门走访成本极高，且领取率长期卡在 24% 左右。 按成功兑付件数结算 + 年度服务费。 他们已有预算、已有 KPI、已有监管压力，只缺一个能把触达-兑付转化率提上去的可信通道。这是最容易被验证的付费方。
银行 / 运营商 / 平台 降低投诉量与监管处罚风险、提升满意度、避免投诉公示带来的声誉损失。 按转化解数或年度订阅。 12315 已集中公示投诉 2624.5 万条、公示率 98.4%——投诉被公开本身就是成本，用一个可信第三方前置化解对企业是净收益。
监管机构 / 消协 提升纠纷源头化解率，降低行政调解负荷。 项目制 / 公共服务采购。 2025 年已推动 27.9 万家企业接入在线纠纷解决机制、源头处理 1232.5 万件——政策方向明确是「把纠纷化解前移」。
双边飞轮

用户授权越充分 → 发现越准、误报越低 → 兑现率越高 → 机构越愿意开放官方接口与数据 → 兑现更容易更快 → 用户更愿意授权。

关键设计：B 端接入必须是「让用户更容易拿到钱」，而不是「帮企业少赔钱」。一旦用户感知到 Agent 站在企业一侧，全部信任资产归零——这同样是 DoNotPay 与代退黑产的覆辙。产品与 B 端的合作条款中，必须写死不得以任何方式向用户做出不利推荐。

冷启动路线：先挑「规则清晰、闭环最短」的域

PHASE 1 · 0–3 个月
单域突破：航空出行
选择理由：法规与承运人《运输总条件》公开且已备案、金额分档固定、延误数据可公开核验、闭环短（10 个工作日内必须答复）。 目标不是 GMV，而是跑通 EV 闸门与 p_success 校准方法论，并把单位兑现成本压到 ¥15 以下。
PHASE 2 · 3–9 个月
扩域 + 首单 B 端：叠加电商价保与会员续费，签约第一家保险公司
价保与续费频次高、数据全在平台内、验证快，是训练主动性的最佳场景。 同步用 Phase 1 的兑现率数据去谈保险公司——把「我们能把你 24% 的领取率提到多少」变成可签的对赌条款，这是 B 端破冰的抓手。
PHASE 3 · 9–18 个月
全品类权益图谱 + 机构侧接入
扩展到保险、通信、金融、教育、房屋六大域，开放机构侧接入标准。 此时的核心资产已经不是 Agent 本身，而是那张带着历史成功率、被十几万次真实兑现校准过的权益图谱——这才是模型能力无法直接覆盖的东西。
08
如果真由我来做：三个最难的取舍
产品方案的价值，一半在于它选择了不做什么。以下是我认为最容易被做错、也最能检验判断的三处。
取舍一不追「发现量」，追「接收率」

最容易犯的错，是把「发现了多少条权益」当核心指标，于是放宽判定阈值、大推特推。结果是短期数据好看，长期用户关闭推送、卸载、并把主动式产品永久拉黑。

我选择用 EV 闸门硬约束发现量，把主动接收率和误报率放在比 SEV 更靠前的考核位置，即使这让早期的数字难看得多。

取舍二不碰「代理执业」，只做「武装用户」

产品定位上有一条危险的捷径：宣称「AI 替你打官司」——DoNotPay 因此被 FTC 处罚、被律协围攻、信任崩塌，19.3 万美元只是显性成本。

我选择把产品严格定义为「武装用户」：所有对外行为以用户名义、经分级授权发出；Agent 提供的是依据、材料、话术与追踪，而不是法律代理。这牺牲了部分想象空间，但换来了合规、B 端合作资格与长期信任。

取舍三不做通用入口，从最窄的域切

这个类目最大的诱惑是「全品类权益平台」——听起来性感，但每个域的条款、举证、话术、时限都不同，全铺的结果是哪一类都判定不准，误报率失控。

我选择先用单一域（航空出行）跑通方法论，把 p_success 校准、成本结构、协商话术库这几件事做成可复制的模板，再横向复制。慢，但每一步都可验证。

一句话总结这个作品想证明的能力

不是「我能做一个 Agent」，而是「我能判断哪个 Agent 值得做，并且能用数据证明它为什么值得做」。

这个方向所有的关键结论——瓶颈不在提醒而在行动链、供给真空在合法低价侧、主动性是需求决定的架构约束而非偏好、壁垒在权益图谱而非模型——都不是来自灵感，而是来自对官方披露数据的重新拆解。这是我认为一个 AI 产品经理最该被评估的能力。

常见问题 · FAQ
你可能想问
我的账单、保单数据安全吗？
最小必要授权、分级授权、随时可撤销、数据可导出。凡涉及个人敏感信息外发（如身份证件），一律触发 L2 显式授权并单独留痕，默认不执行。
不成功真的不收费吗？
C 端按结果计费——钱实际到账后才按比例抽成。EV 闸门保证只推送值得办的权益，不会为了收费而打扰你。
归仓和律师有什么区别？
归仓不替代律师、不做法律代理。它做的是「武装用户」：依据、材料、话术与全程追踪。涉及诉讼或复杂案件，仍建议转交专业律师。
银行、保险公司不是会提醒吗？
它们只看自家、出于合规压力、且正是被你当成诈骗的那条短信。归仓跨源、站在你这一侧、每张权益卡都附可复核的条款原文。
怎么开始用？
三步：① 授权你愿意的数据源；② 等归仓完成首次巡航报告；③ 对看得上的权益一键授权，剩下的交给它。
