# 归仓 Reclaim · 作品集说明

> 主动式个人权益 Agent — 一个持续替你发现并兑现「应得而未得」权益的个人 Agent

---

## 这是什么

归仓不是一个「帮你更快做某件事」的提效工具，而是一个**让原本根本不会发生的行为发生**的 Agent。

大多数人不知道自己有哪些权益——电商价保差价、会员自动续费追回、保险生存金、运营商超额退费——即使知道，也因为举证难、程序复杂、单次收益低而理性选择放弃。归仓替你完成从「发现」到「拿到」的完整行动链。

## 为什么这是「创造新价值」而不是「提效」

四条判据全部成立：

| 判据 | 归仓 |
|---|---|
| **行为从无到有** | 没有它，这件事根本不发生。睡眠保单被提醒 732 万件，实际领取仅 180 万件（24.65%），约 3/4 的人知道也不动 |
| **供给角色不存在** | 大量小额争议难以覆盖专业人工成本，机构只处理自家权益，职业代退又带来欺诈与个资风险 |
| **非 LLM 不可** | 跨源聚合、自然语言条款理解、长周期多轮执行、主动性触发，缺一不可 |
| **价值可结算** | 每笔兑现金额确定，可按结果收费（成功金额的 10–20%） |

**反事实检验**：没有归仓，用户不会主动去查价保差价、不会去追回未使用的会员续费、不会去领取睡眠保单生存金。这些行为的存量为零。

## 2026 年市场差异化

市场已有订阅取消、航班索赔、FBA 退款和保险理赔等垂直产品，它们证明了“异常发现 + 跟进 + 结果收费”的需求。归仓的差异不是宣称没有任何竞品，而是将跨来源发现、可核验判定、EV 打扰闸门、分级授权和可审计行动包组合为一个站在用户一侧的主动系统。

## 核心设计决策

### 五层 Agent 架构

1. **发现层 Discovery**：事件驱动扫描授权数据源，不是定时拉取
2. **判定层 Adjudication**：三问判定（成立吗？依据是什么？EV 多少？），EV = 期望金额 × 成功率 − 兑现成本
3. **兑现层 Enforcement**：多 Agent 协作（材料 → 文书 → 协商 → 追踪 → 升级）
4. **合规闸门 Compliance Gate**：分级授权（L0 自动 / L1 一键确认 / L2 显式授权 / L3 永久禁止），拦截虚假陈述、越权行为、未授权信息外发
5. **信任层 Trust**：依据可复核、过程可审计、结果可对账

### 三个最难的取舍

1. **不追发现量，追主动接收率** — EV 闸门硬约束发现量，宁可早期数字难看
2. **不碰代理执业，只做武装用户** — 不做「AI 替你打官司」，DoNotPay 的教训
3. **不做通用入口，先用影子模式选域** — 比较保单满期、自动续费和航旅延误的准确性、证据完整率、主动接受率与闭环时长

### 首个域的进入标准

在 20–30 个脱敏真实样本中达到：误报率 < 5%、主动接受率 > 55%、关键证据可获取、预计 14 天内可闭环。不在没有真实样本时凭市场报告直接宣称一个域存在“绝对真空”。

## 如何演示 Demo

1. 打开 `interactive-demo/index.html`
2. 在“授权记录”中直接使用演示样本，或粘贴自定义文本
3. 调整 EV 最低阈值，启动本地扫描
4. 在“权益队列”比较保单、航旅、自动续费与低价值价保的不同处理路径
5. 选择一项准备行动包，导出 JSON 或复制草稿
6. 确认授权边界，再在“授权与审计”查看本地留痕

MVP 内置 4 个规则样本，覆盖高可行、需补证和低价值折叠三种路径。所有对外执行都被明确停在演示边界内。

## 这个作品想证明什么

不是「我能做一个 Agent」，而是「我能判断哪个 Agent 值得做，并用数据证明它为什么值得做，再把它从概念变成一个可以真实运行的交互产品」。
